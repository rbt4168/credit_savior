## 測試層次

| 層次 | 使用資料 | 驗證目的 |
| --- | --- | --- |
| 純邏輯／Store | 可控制 clock、SQLite 暫存庫、標準 DTO。 | 版本雜湊、原子 claim、lease、去重與狀態轉移。 |
| Browser 整合 | 去識別化 fixture 及可控制測試站。 | DOM、分頁、上傳、回執與播放器行為。 |
| 故障注入 | 在指定 side-effect 邊界強制終止。 | 重啟後沒有盲目重傳、任務與產物可恢復。 |
| NTU COOL 實測 | 指定測試課程與代表性題目／影片。 | fixture 契約與平台當前行為一致。 |
| 24 小時常駐 | 測試課程、持續連網主機。 | 排程缺口、資源消耗、恢復與並行。 |

先證明一種文字／檔案題型的完整流程，再加入程式題與第二種播放器。測試站通過不代表真實 NTU COOL 已整合；各平台實測結果必須另行記錄。

## 測試站能力

測試站提供有狀態的帳號、指定課程、分頁作業列表、附件下載、文字／檔案提交與影片控制。可注入：

- 回應延遲、timeout、明確拒絕及失效登入。
- 最終提交已成功但 HTTP 回應遺失。
- 上傳成功但最終提交尚未按下。
- 回執延遲顯示與另一個瀏覽器先提交。
- 同 URL 附件內容替換、題目版本變更。
- 播放 ended 與平台進度互相獨立的結果。
- iframe 播放器、緩衝、paused 與永久停滯。

故障注入提供具名 hook，僅測試使用，不以正式 .env 開啟危險模式。

## 驗收案例

| ID | 情境 | 預期結果 |
| --- | --- | --- |
| CFG-01 | 課程清單空值、非數字、重複 ID。 | 空值／無效值阻止 run；重複去重；不擴大至全部課程。 |
| CFG-02 | 密碼含 #、空白、引號；程序 env 覆蓋 .env。 | 讀值正確，日誌與 DTO 不含 secret。 |
| CFG-03 | 路徑包含 ..、指向根目錄外或 symlink 逃逸。 | 設定驗證拒絕。 |
| AUTH-01 | 首次登入後重新建立 context。 | 狀態重用成功，核對同一帳戶。 |
| AUTH-02 | 過期 cookie／損毀狀態檔。 | 有限恢復，不覆寫有效檔案為損毀內容。 |
| AUTH-03 | 登入被拒、MFA、課程 forbidden。 | 各有獨立原因；不無限重新登入。 |
| SCAN-01 | 模型解題 3 分鐘，影片播放 30 分鐘。 | scanner 仍按 600 秒開始，不使用 worker 頁面導覽。 |
| SCAN-02 | 系統 clock 校正或睡眠跨三個週期。 | 不累積時間漂移，錯過輪次合併一次。 |
| SCAN-03 | 兩頁列表、重複分頁、載入未完成。 | 正常走完整列表；異常不當成空列表。 |
| SCAN-04 | 新作業、相同作業、附件 bytes 改變。 | 下輪成功掃描發現；相同版本只有一個 job；附件改變建立新版本。 |
| SCAN-05 | 某課程失敗、全輪超過 480 秒。 | 保存 partial、cursor 與未掃描範圍，其他課程結果保留。 |
| DB-01 | 兩次 claim 同一 job、重複 enqueue。 | 同一 lease owner 持有，唯一限制阻止重複 job。 |
| DB-02 | 舊 owner 在新 owner claim 後 checkpoint。 | 零筆更新，舊 worker 停止寫入。 |
| DB-03 | 同作業不同版本建立 pending attempt。 | partial unique index 阻止第二個未決提交。 |
| DB-04 | 檔案寫完 DB 未 commit、DB 引用檔案遺失。 | 前者清理孤立檔；後者 needs_input，不提交。 |
| HW-01 | 支援的文字／PDF 作業。 | 題目 → solver → validator → 提交 → 平台回執完整通過。 |
| HW-02 | 模型無效 JSON、缺資料、回傳任意路徑。 | 拒絕不合契約輸出；不執行任意命令。 |
| HW-03 | 大小、格式或已知測試失敗。 | 不進 ready；修正請求共用三次模型額度。 |
| HW-04 | 提交前題目變更或已有人工提交。 | 舊版本取消；不覆寫已提交結果。 |
| HW-05 | 已過 due 但仍允許遲交、或 lock 已關閉。 | 前者記錄 late；後者不提交。 |
| HW-06 | 最終點擊之後失去回應。 | 只讀核對；平台成功時確認一次，未知時不再次點擊。 |
| HW-07 | 平台明確拒絕與回執只暫時不可見。 | 拒絕可修正；不可見不推定提交失敗。 |
| HW-08 | 沒有隔離 runner、程式無限迴圈。 | 不在主機執行；有限時間終止，保存診斷。 |
| VID-01 | ended 但平台進度未知。 | played_unverified，不能 succeeded。 |
| VID-02 | 暫停、短緩衝、超過 60 秒 stall。 | 正常恢復，重開最多三次，不無限循環。 |
| VID-03 | checkpoint 後中斷與 source revision 改變。 | 同來源有限重播；新來源不用舊位置。 |
| VID-04 | 平台缺漏片段、延遲完成。 | 補播最多兩輪，有限核對後保存可靠狀態。 |
| VID-05 | iframe／YouTube 與不支援播放器。 | 已整合者正常控制，未整合者保存原因。 |
| OPS-01 | 同時啟動兩份 run／auth。 | 第二份被 OS 鎖拒絕，不競爭登入狀態。 |
| OPS-02 | browser crash、worker 例外、磁碟滿。 | 分別局部恢復或退出；不丟失未決提交。 |
| OPS-03 | Ctrl+C 與 30 秒關閉逾時。 | 保存 checkpoint／intent，重啟走正確階段。 |
| OPS-04 | 24 小時正常運行。 | 144 個排程時間格均有結果，無重複提交與未解釋的巡檢缺口。 |

## 提交崩潰邊界

對以下每個邊界各做一次 kill／restart：

1. 答案檔保存後、DB checkpoint 前。
2. prepared attempt COMMIT 後、上傳前。
3. 上傳完成後、dispatching COMMIT 前。
4. dispatching COMMIT 後、最終點擊前。
5. 最終點擊後、回應前。
6. 平台成功後、本機回執保存前。
7. 回執保存後、job succeeded COMMIT 前。

邊界 4 與 5 本機狀態可能相同，恢復不可假設哪一邊發生；必須核對平台，無可靠證據時停止重送。每案統計測試站實際最終提交次數，而非只檢查函式被呼叫次數。

## 24 小時驗收定義

量測時間窗採 [t0, t0 + 24h)，啟動立即掃描計為第一格，包含 144 個 600 秒格。正常環境下開始時間偏差目標不超過 5 秒；成功完整輪次包含所有指定課程，單輪不超過 480 秒。

記錄每格 scheduled／started／completed、CPU／記憶體摘要、browser 重建數、queue 長度、未決提交與錯誤。故障注入與正常 soak 分開：正常 soak 要零未解釋缺口，故障測試允許中斷但需通過恢復證據。

## 交付證據

每一階段產出本機或 repository 可公開的去識別化驗收摘要：環境版本、案例 ID、結果、可重現步驟與限制。原始課程題目、帳密、cookie、影片紀錄與學生資料不提交到 Git。

目前本次只驗證文件結構、相對連結、設定文件一致性與 DDL 合法性；以上是未來系統的驗收規格，不能宣稱已通過真實網站測試。
